### First theorem on the imported design (Veda/Designs/Counter.lean)

Closing the term-vs-file gap: theorems need the circuit as a
compile-time term, but the artifact is a file produced by external
tools. The chain is:

1. `counterMlir` — the generic MLIR embedded as a string literal; LSpec
   checks it is byte-identical to the file on disk (which CI's
   import-roundtrip job keeps honest against the pinned CIRCT release).
2. `counterCircuit` — the transcribed `Circuit` term;
   `counter_import_agrees` re-runs the importer on `counterMlir` at
   proof time and checks equality (`native_decide` — the one
   deliberately reflection-trusted link, reported by name in every
   build by the axiom gate).
3. `stepFn_spec` — interpreter characterization: `stepFn [⟨8,q⟩] i =
   [⟨8, if rst then 0 else if en then q+1 else q⟩]`, by 4-way case
   split on the two input bits (kernel-`decide`d over `BitVec 1`) and
   `simp`-evaluation of the netlist fold.
4. `counter_wraps` — **the M2 theorem**: `holds D (always (count=255 ∧
   en ∧ ¬rst |-> ##1 count=0))` over all valid traces and all power-on
   values. Kernel-only: after the `##1` match is exhibited, trace
   validity + `stepFn_spec` reduce it to `255#8 + 1#8 = 0#8`.

Axiom gate after this change: 570 declarations, exactly 2
reflection-trusted (`bv_smoke_sub_lt`, `counter_import_agrees`) — the
temporal theorem itself carries only the three standard axioms. (An
earlier draft used `bv_decide` for the bit case-split; `decide` over
the two `BitVec 1` values is kernel-checkable and strictly better for
the trust story, so `bv_decide` remains exercised only where SAT is
genuinely needed.)

### Lean proof-engineering notes (for future imports)

- Keep `Val.castTo`/accessor definitions in **simp-normal form**
  (`l[i]?.getD` rather than `l.getD i`), or hypotheses and goals drift
  apart under `simp`.
- `rfl`-lemmas `castTo w ⟨w, v⟩ = v` avoid dependent-`dite` cast
  pain entirely; never unfold `Val.castTo` in the main simp set.
- `rw` is brittle across `Val`/`Sigma` defeq boundaries
  ("not type-correct under instances transparency"); prefer `have` with
  type ascription (defeq is checked at default transparency) and
  `exact`.

## What was tried / what happened

### Environment: egress policy shapes the whole setup

The development sandbox runs inside the `tibrewalrachit/circt` fork with an
egress policy that only allows this repository on github.com (plus
raw.githubusercontent.com, pypi, npm, crates). Consequences:

- **No `llvm/circt` release downloads, no `git clone` of llvm-project or
  slang, no Lean toolchain from leanprover releases** (the
  releases.lean-lang.org "mirror" 302s to GitHub release assets, which the
  proxy blocks). Building CIRCT from source is also impossible (the LLVM
  submodule cannot be cloned).
- **Solution:** `.github/workflows/veda-bootstrap-tools.yml` runs on a
  GitHub Actions runner (full network) and mirrors the pinned artifacts to
  a release named `veda-tools-v1` **on this fork**, which the sandbox can
  download. Assets + sha256s are in `veda/toolchain.lock`.
- Side effect, intentional and reversible: the bootstrap workflow ran
  `gh workflow disable uploadReleaseArtifacts.yml` on this fork first.
  That workflow triggers on `release: created` and would have launched
  CIRCT's full multi-platform release build matrix (hours of CI) and
  uploaded its artifacts into our mirror release. Re-enable with
  `gh workflow enable uploadReleaseArtifacts.yml` if ever needed.
- LSpec cannot be a Lake *git* dependency for the same reason; it is
  vendored under `veda/vendor/LSpec` (commit in `toolchain.lock`).

### Reading notes

**CIRCT LTL dialect** (docs/Dialects/LTL.md at this checkout):

- Two types + hierarchy `i1 <: !ltl.sequence <: !ltl.property`. Sequences
  are regexes over time; properties add quantification.
- `ltl.delay %s, N[, M]`: match between N and N+M cycles in the future;
  **omitted length = unbounded (finite) delay** (`##[N:$]`).
- `ltl.concat` aligns *end of LHS with start of RHS in the same cycle*
  (`##0` semantics); infix `a ##N b` desugars to `concat(a, delay(b,N,0))`.
- `ltl.implication` models **overlapping** `|->` only; `|=>` desugars via
  `concat(s, delay(true,1,0))`. Deliberately keeps implication clock-free.
- **`ltl.until` is weak; `ltl.eventually` is strong** — must be mirrored
  exactly in Veda/Ltl (rule 3).
- `ltl.repeat`/`goto_repeat`/`non_consecutive_repeat` for `[*]`, `[->]`,
  `[=]`. Unbounded repeat is *not* LTL-expressible; it's the one truly
  regex-flavored primitive.
- No local variables, no aborts (`accept_on`/`reject_on`), no
  `first_match`. `disable iff` becomes the `enable` operand of
  `verif.assert`.
- Doc oddities to resolve by differential testing in M3 (recorded in
  semantics-decisions.md): `always p` is shown mapping to `ltl.repeat`,
  and some snippets give `p1 until p2 : !ltl.sequence` where a property
  would be expected.
- `$rose/$fell/$stable/$past` lower to explicit `seq.compreg` + compares
  — i.e. they arrive at Veda as ordinary state, not as temporal ops. Good:
  the importer doesn't need special cases for them.

**Verif dialect**: `verif.assert/assume/cover` (+ `enable`), and
*contracts* (`verif.contract`, `require`/`ensure`) with the
check-vs-apply duality (check: require→assume, ensure→assert; apply:
require→assert, ensure→assume). This is exactly the assume-guarantee
shape planned for `Veda/Compose` in M5 — CIRCT already has the IR-side
vocabulary for it.

**Sparkle** (Verification_Framework.md): proof-pattern taxonomy
(invariant / round-trip / bounded liveness / refinement), the
`cases <;> simp [nextState]` FSM idiom, LSpec for executable sanity
checks. Sparkle proves *per-transition* lemmas on hand-written specs;
Veda differs in that properties are stated over Nat-indexed traces of
*imported* designs, so Sparkle code is not directly reusable — but the
`nextState`-enumeration idiom will reappear inside our k-induction leaf
obligations.

**Normal Computing blog** ("580K lines in 43 days"): iteration-log
discipline (their fork logged 1,554 iterations — this file is Veda's
version of that), test-suite-driven objectives, and the reference result
we aim to beat: circt-bmc proves OpenTitan `prim_count` assertion-clean
**up to 20 cycles**; Veda's M4 target is the same design for all time and
all widths.

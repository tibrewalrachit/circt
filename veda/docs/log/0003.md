# Log 0003 — M2 (part 1): the importer

Date: 2026-07-01 (same session). Objective: generic-MLIR → `Design`
import pipeline, validated on the counter.

## What was tried / decided

- **Netlist IR + total interpreter** (Veda/Import/Netlist.lean): `Val`
  (width-indexed bitvector), `CRef` (input/reg/node), `CNode` covering
  `hw.constant`, variadic `comb.{add,mul,and,or,xor}`, `comb.{sub,mux,
  icmp,extract,concat,replicate}`, `seq.to_clock`, plus explicit
  `uninterp` for anything else (rule 2; `Circuit.uninterpreted` feeds
  the ledger downgrade). `Circuit.design` interprets a circuit as a
  `Design` with `List Val` state; `init` constrains only the state
  *shape*, so register power-on values stay universally quantified —
  exactly what `seq.firreg` without preset means. `stepFn_shape` proves
  shape is invariant.
- **Line-based parser** (Parser.lean): `--mlir-print-op-generic` output
  is one op per line for flat hw modules; parses results/op/operands/
  attrs/types per line, ports from `!hw.modty<...>`. Any unrecognized
  shape is a hard error — the importer never guesses.
- **Elaborator** (Elab.lean): two passes (registers + symbol table,
  then nodes), followed by **topological sorting** — `hw.module` bodies
  are MLIR *graph regions*; the counter's `comb.add` textually precedes
  the register it reads. Combinational cycles are a hard import error.
  Width metadata is recorded per node; interpreter-side coercion is an
  unreachable-after-validation fallback.
- **Differential level 1** (Tests/Import.lean): imported counter vs.
  hand-written Lean twin, 300 pseudo-random steps + directed
  reset/enable cases, bit-exact. Also structural checks (ports, one
  8-bit `count_q`, no uninterpreted ops).
- Lean v4.31 API churn worth remembering: `String.trim` →
  `String.trimAscii : String → String.Slice` (append `.toString`),
  `String.drop` returns `Slice`, `List.get?` is gone (use `l[i]?`).
